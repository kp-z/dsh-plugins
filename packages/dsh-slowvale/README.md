# dsh-slowvale

把 Slow Vale 的城市接到 DSH：**角色有 persona，一个角色一张嘴（DSH 会话），嘴可以换，人能说话也能互相说话。**

## 现在能干什么（已验证）

| 能力 | 证据 |
| --- | --- |
| 角色 ↔ 会话绑定，一个角色同一时刻只有一张嘴 | 5 个不变量用例 |
| 换嘴 = 归档 + 新开，历史可回放 | rotate / archive 用例 |
| 上下文按层注入：人 → 场合 → 处境 → 关系 → 心情 → 记忆 | 6 节断言 + 加层不改调用方 |

| presence：不瞬移 / 不斜飘 / 到点吸附 | 5 个手感用例 |
| 成本：每 tick 预算 + 并发上限 + 超时 | 6 个护栏用例 |
| 全链路 | e2e：短信 → 记忆 → 换嘴 → 互聊 → 预算 → 在场 |

## 架构

\`\`\`
Character   人：外观 / 家 / 工作地 / persona        （与"谁在说话"无关）
  └ Persona 性格 / 说话方式 / 在意的事 / 不做的事     （稳定）
      └ ContextBundle  这次开口看到什么             （现算，分节，每节带 source）
          └ Session  嘴：一个角色同一时刻只有一张   （可归档、可换）
\`\`\`

世界侧的四个部件：\`Messenger\`（短信线程）、\`Conversations\`（互聊）、\`Budget\`/\`Guard\`（成本与并发）、\`PresenceView\`（移动）。

## 三条设计决定

1. **一个角色一张嘴。** "工作号 + 私人号"是聊天软件的习惯，不是人的习惯；两个活会话会让同一个人在两份上下文里各说一套。
2. **注入是分节的。** 一整段 prompt 没法单测、没法局部替换、坏了定位不到哪层。加一层 = 加一个 provider。
3. **对话与短信都过世界。** 直连会绕过"谁在场、谁有话说、花了多少钱"，回放也查不到"这句是回什么说的"。

## 与前端的关系

**不改前端一个字节。** 前端是这台游戏的引擎，是一份契约；所有游戏性由后端供对。
