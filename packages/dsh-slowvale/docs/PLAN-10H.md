# 10 小时计划：把 Slow Vale 做成 DSH 插件

> 术语校正：需求里的「绘画」按同音理解为 **「会话」(session)**。
> 即：把 DSH 会话当作可以被派活、可以互相说话的实体，绑到城市里的人物身上。
> 如果你说的确实是"绘画"（画画），请打断我——两者骨架一样，但内容层完全不同。

## 0. 目标

城市里的人 = 有 persona 的角色；每个角色可以挂**多个 DSH 会话**；
会话之间能互相说话；这些交互通过插件暴露到 Slow Vale 前端已有的 API 上。

## 1. 三个设计判断（先定，免得返工）

**判断一：会话是"嘴"，角色是"人"。**
一个会话只能是**一个人**在说话（否则聊天记录会精神分裂）；反过来一个人可以有多张嘴
（工作号、私人号、旁观号），它们共享同一个 persona 与记忆，但看得见的东西不同。

**判断二：绑定是一张表，不是一个字段。**
现在 agent-world 的 boundAgentId 是一对一字段，撑不住多会话。
改成 append-only 的绑定表（含 unboundAt），这样"谁在什么时候代表谁"可回放。

**判断三：会话之间的对话要过世界。**
A 对 B 说话不能直接调对方的 send_message——那会绕过世界、破坏回放。
应当是：A 说 → 世界记录一条 message → 世界决定 B 能否收到 → 投递。

## 2. 十个小时

| H | 一块 | 产出 | 验收 |
| --- | --- | --- | --- |
| H1 | 骨架 + 绑定模型 + 3 个 persona | 新包、绑定表、3 个角色、单测 | 绑定不变量全绿 |
| H2 | 会话接入：创建/接管 DSH 会话 | sessionController 适配、会话池 | 能开一个会话并要它回一句 |
| H3 | persona 注入 | 组装 system prompt | 同一个问题，三个角色答得不像一个人 |
| H4 | 会话之间对话 | 世界中介的 A→B 消息、投递规则、防环 | A 让 B 说话，双方记录一致 |
| H5 | 多会话绑定 | primary/secondary/observer + 频道可见性 | 一个角色两个会话，看到不同上下文 |
| H6 | 派活：任务 → 会话 turn | 任务模型 + 派发 + 回执 | 派任务，会话执行并回写 |
| H7 | 记忆与人格一致性 | 记忆摘要注入、跨会话合并 | 换会话仍记得昨天的事 |
| H8 | 投影到前端 | HUD 显示"由哪个会话代表"、手机开新会话 | 前端能看到绑定关系 |
| H9 | 稳定性与成本 | 并发上限、超时、重试、预算护栏 | 压 10 个角色不雪崩 |
| H10 | 验收与文档 | 3 会话 e2e、README、发布 | 浏览器里完成一次三角对话 |

## 3. 每小时纪律

1. 先读 PROGRESS 确认真实状态（不信任记忆）；
2. 用 ≤5 行写下这一小时的一块（做不完就再切小）；
3. 改一处跑一次测试；
4. 收尾更新 PROGRESS：做了什么、为什么、卡在哪、下一小时从哪开始。

## 4. 明确不做

多世界并发、付费/抽卡、重写前端、角色自主发起任务（本版只有人/系统派活）。
