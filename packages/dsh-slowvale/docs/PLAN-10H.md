# 10 小时计划：把 Slow Vale 做成 DSH 插件（v3）

> 术语：需求里的「绘画」按同音理解为 **「会话」(session)**。
> v2 的关键修订来自你的提议：**角色要有自己的数据模型，角色与会话彻底解耦**。
> 我把它做得更彻底一点——不是"会话去注入 persona"，而是**会话每次开口向世界要一份 Context Bundle**。

## 0. 分层（这是 v2 的核心）

```
Character   人：住在哪、长什么样、什么性格          （持久，与"谁在说话"无关）
  └ Persona 人格：traits / speech / goals / taboos （稳定，不随场合变）
      └ ContextBundle  这次开口看到什么           （现算，按场合/处境/记忆组节）
          └ Session   嘴：一个会话只代表一个人    （可开可关可换）
```

**为什么这样解耦是对的：**

- 换会话 ≠ 换人。人不变，只是换了一张嘴（工作号 / 私人号 / 旁观号）。
- 加注入层 ≠ 改会话。加一个 provider 就行，`buildContext` 一行不动。
- 每句话都能回答"他当时看到了什么"：bundle 里每节都带 source。

**为什么 bundle 要分节，而不是一整段 prompt：**

一整段散文没法单测、没法局部替换、写坏了也定位不到是哪一层。
分节之后：一段 prompt = 若干节，每节标来源，增删层只是增删一个 provider。

## 0.5 v3 的关键简化：一个角色只有一张嘴

原方案里"一个人可以有多张嘴（工作号/私人号/旁观号）"被砍掉了。理由是它不解决问题，只制造问题：

- "工作号 + 私人号"是**聊天软件**的习惯，不是**人**的习惯。街上走的那个人只有一张嘴。
- 两个活会话会让同一个人在两份上下文里各说一套，回放时说不清哪句算数。
- 每多一个活会话，就要多一套路由规则（谁代表他发言、谁能看到什么），而收益只是"语气不同"。

于是模型变成：

```
角色 ──(至多一个活会话)── 嘴
  └ 归档的历史会话（聊天记录留着，可查"某小时是谁在说话"）
```

换一种状态（换场、换话题、会话坏了）就 **rotate**：归档旧的、开新的。
人和记忆不换，换的只是嘴。这也顺便解决了记忆归属问题：**记忆属于角色**，所以换嘴之后他还记得。

## 2. 角色模型里放什么（当前取舍）

放：id / name / pronouns / appearance / home / work / persona / createdAtTick。

不放（以及为什么）：
- **不放"当前在哪、在干嘛"**——那是世界状态，随 tick 变；
- **不放"说话方式"**——那是 persona 的投影，且要按 channel 变；
- **不放会话 id**——绑定在 BindingTable 里，因为可以换、可以多个；
- **不放记忆正文**——记忆是检索出来的片段，进 bundle 的 memory 节，不进角色本体。

## 3. 每小时的纪律

1. 先读 PROGRESS 确认真实状态（不信任记忆）；
2. 用 ≤5 行写下这一小时的一块（做不完就再切小）；
3. 改一处跑一次测试；
4. 收尾更新 PROGRESS：做了什么、为什么、卡在哪、下一小时从哪开始。

## 4. 明确不做

多世界并发、付费/抽卡、重写前端、角色自主发起任务（本版只有人/系统派活）。
