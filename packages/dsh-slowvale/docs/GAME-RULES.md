
# 游戏性契约：后端必须原样供上的东西

> 立场：**前端就是这台游戏的引擎，它是一份契约，不是一份可以随手改的代码。**
> 所有"游戏性"都必须由后端喂对；一旦后端喂错，玩家感受到的不是 bug，是"这游戏变差了"。
> 所以本项目有一条硬规矩：**site/ 一个字节都不改**，并有用例守着。

## 1. 为什么不能改前端

- 前端已发行、已被玩家验证过；它的手感（走路速度、转身、气泡节奏、镜头跟随）是调出来的，不是猜出来的。
- 前端产物有 2401 个文件 + sha256 清单（\`slowvale-mirror/_bundle/files.json\`），改一个字节就是另一个游戏。
- 改前端会把"我们的问题"变成"全世界的 bug"，而且**无法回滚**：没人能保证改回去一模一样。

守门：\`slowvale-mirror/scripts/verify.mjs\` 逐文件校验 sha256。任何一次改动后先跑它。

## 2. 后端要供对的规则清单

| 规则 | 前端拿它做什么 | 我们现在的状态 |
| --- | --- | --- |
| 位置 (x, y) 与朝向 | 决定角色画在哪、朝哪 | 结构层已有；**步进规则未定** |
| 移动速度上限 | 决定"走路"还是"瞬移" | 待定：超出上限会变成滑行/闪现 |
| 面朝四向 | 决定用哪一行动画帧 | 待定：必须 up/down/left/right，不能斜向 |
| 行走/待机帧 | 6 帧、rate 8 | 已知（PersonalityPicker 里的表） |
| 在场判定 | 谁出现在这个场景、谁从地图消失 | 结构层有 presence；**进出场的时机未定** |
| 场景切换 | 换背景、换家具、换可交互物 | 结构层有 scene；**切换时序未定** |
| 时钟 (day / 时段 / 星期) | 昼夜、店铺开关、日程 | 结构层有 clock；**规则未定** |
| 体力/饥饿/卫生 | 动作能否执行、走路是否变慢 | 完全没有 |
| 工作状态 | 头顶状态、能否被搭话 | 完全没有 |
| 日程 | 早上出门、晚上回家 | 完全没有 |
| 市场/商店营业时段 | 面板能否交易 | 只有空结构 |

"结构层"= 字段存在且形状合法（面板能开）；"规则"= 值随时间与行为正确变化（游戏像游戏）。

## 3. 防回退的三道闸

1. **产物闸**：\`verify.mjs\` 校验前端 2401 个文件 sha256 —— 谁动了前端，立刻红。
2. **契约闸**：后端输出的 presence/visual 必须过形状校验（字段、枚举、范围）。
3. **手感闸**：移动必须满足"每 tick 位移 ≤ 上限""朝向只能四向""到达要吸附"——
   这几条正是"瞬移"与"滑行"的判别式，用单测钉住，而不是靠肉眼看。

## 4. 已知的未知（下一步必须抓）

- 真实服务端的 \`visual\` 帧长什么样（我们只反推到 kind 名，没拿到内容）；
- char 移动是"服务端逐帧下发"还是"服务端给目标点、前端自己插值"；
- 场景切换的握手（先 \`scene_state\` 还是先 \`visual\`）。

这三条决定"走路看起来像不像走路"，抓包/对照是下一阶段的重点。
