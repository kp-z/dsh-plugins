
# 前端接线：三个面，别混为一谈

左下角那台"手机"其实对应**两个不同的面**，混在一起会做错。

## 面一：HUD 聊天流（左下角）

- **是什么**：场景里"当前在场的人"的对话流，前端叫 \`sceneStream\`，显示"还没有人说话"。
- **怎么来**：SSE 推送（\`update\` 信封），不是拉取端点。
- **怎么发**：\`POST /game/player/message { role_id, text }\`。
- **我们的接法**：这个 POST 进 \`Messenger.receive\`；回复经 SSE 推回去。
- **未定**：**聊天条目的信封形状**（entry 里除了 text 还有哪些字段）。这是下一件必须挖的事。

## 面二：手机面板里的短信（App 内）

- **是什么**：\`/game/phone/sms/threads\`（会话列表）与 \`/game/phone/sms/thread\`（消息）。
- **前端读什么**：\`threads\` 数组（经 \`nn()\` 归一化）；未读数来自 \`role.phone.sms.total_unread_count\`。
- **我们的接法**：\`Madnessenger\` 的线程直接映射成这两个端点。
- **未定**：线程条目的字段集合（title / preview / 参与者）。已探到存在 \`total_unread_count\`、
  \`latest_message_row_id\`，其余要靠面板报错逐个逼（结构层的做法）。

## 面三：在场与移动（画面）

- **是什么**：\`role_presences\` 里的 \`location { place_id, x, y, facing }\`。
- **形状已验证**：整数像素、四向朝向、place_id 用 \`place:*\` 命名。
- **我们的接法**：\`view/presence.ts\` —— 按步长推进（手感契约）、取整输出（前端契约）。
- **已定**：不瞬移（每帧 ≤ 步长）、不斜飘（四向主轴）、到点吸附。

## 接线顺序（为什么这么排）

1. **移动**（面三）：它是玩家一直在看的，错了立刻"游戏变差"。
2. **HUD 聊天**（面一）：发一句、回一句，是"AI 活着"最直接的证据。
3. **手机短信**（面二）：更完整但触发频率低，最后接。

## 一条纪律

任何一面接线之前，先跑 \`slowvale-mirror/scripts/verify.mjs\`：前端 2401 个文件必须仍然逐字节一致。
接线只允许发生在我们自己的适配层，**不允许动产物**。
