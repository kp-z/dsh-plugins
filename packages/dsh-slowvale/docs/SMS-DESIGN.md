
# 短信入口：左下角那台手机怎么接

## 一句话

**短信是同一张嘴的另一扇门，不开新会话。**

角色此刻的活会话不变；短信只是从"面板上打一行字"变成"从手机发一条短信"。
如果短信去开新会话，就立刻回到我们刚删掉的问题：同一个人在两份上下文里各说一套。

## 链路

\`\`\`
前端 POST /game/player/message {role_id, text}
        │
        ▼
世界：WorldMessenger.send(roleId, text)
        ├─ 记一条 message（属于"这个角色 ↔ 玩家"的线程，不属于会话）
        ├─ 可达性判定：他现在方便看手机吗？
        │     · 在场上、不忙        → 立刻投递
        │     · 在忙（走路/干活）  → 排队，等当前动作结束再投递（"过一会儿才回"）
        │     · 不在这个世界的角色 → NPC 兜底或拒收（带原因）
        ▼
CharacterSessions.say(roleId, text)   ← 已有的活会话；没有就懒开一个
        ▼
回复 → 写回线程 → SSE 推给前端（手机面板 / 头顶气泡）
\`\`\`

## 三个设计判断

**一、线程属于世界，不属于会话。**
短信记录挂在"玩家 ↔ 角色"这条关系上。会话可以归档、可以换，聊天记录不能丢——
否则换个会话，昨天聊的事就没了。新会话靠 memory 层带最近 N 条进来。

**二、没有活会话时是"懒开"，不是"轮换"。**
轮换是针对"他已经在用另一张嘴"（换场、话题变了）。短信进来时他本来没嘴，
那是 open，不是 rotate——归档一个不存在的会话没有意义。

**三、"在忙"要能解释。**
短信不是同步接口。前端不该转圈等；世界先回执"已收到"，
回复到达时再推一条。所以 /game/player/message 的响应是**回执**，不是答案。

## 群聊（compoundGroup / unitGroup）怎么办

一次 fan-out：世界给每个成员各投一条，**每个角色仍各自用自己那张嘴**。
不做"群里的多人同时说话"——那是同一张嘴说多个人的话，做不到也不真。

## 与 DSH 会话的两种接法（都走同一个端口）

| 场景 | 接法 | 说明 |
| --- | --- | --- |
| 角色由插件自己管 | \`open()\`（H2 已实现） | 端口开一个会话，绑给角色 |
| 角色就是用户自己那个 DSH 会话 | \`attach(sessionId)\`（H2 已实现） | 不新开会话，直接把短信喂进已有会话 |

两种对上层完全一样，因为上层只认 \`say(characterId, text)\`。

## 需要前端配合吗

不需要改前端：\`/game/player/message\` 与 \`/game/phone/sms/thread\`、\`/threads\` 都在
API-COVERAGE 的结构层里，把它们从"空结构"换成"真数据"即可。
