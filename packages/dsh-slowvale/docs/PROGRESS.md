# PROGRESS

## 2026-11-20 22:40 · v3 简化：一个角色只有一张嘴

**用户决策**：不能同时绑两个会话；只能归档/解绑之后才绑新的。

**据此做的改动**（净删代码）：
- `BindingRole`（primary/secondary/observer）整个删掉——只有一张嘴就没有"谁代表他"的问题
- `speakerOf()` 删掉，换成 `current()`；`sessionsOf()` 改为"用过的全部会话（含归档）"
- `bind()` 增加不变量：角色已有活会话时直接拒绝，提示先 archive
- 新增 `archive(sessionId, tick, reason)`：写 archivedAtTick + 原因，不删行
- `CharacterSessions` 新增 `rotate()`：归档 + 新开，返回旧会话 id 便于回执
- `open()` 在已有活会话时**拒绝**而不是复用/顶替：复用会把新处境套进旧上下文，顶替会丢掉旧会话去向

**为什么这是简化而不是妥协**：
- "工作号 + 私人号"是聊天软件的习惯，不是人的习惯；街上的人只有一张嘴。
- 两个活会话 = 同一个人在两份上下文里各说一套，回放说不清哪句算数。
- 每多一个活会话就多一套路由规则，收益只是"语气不同"。

**顺带解决的悬案**：记忆归属。既然同一时刻只有一张嘴，记忆属于**角色**——换嘴之后他还记得。
上一轮我问过"工作号和私人号要不要各记各的"，现在这个问题不存在了。

**测试**：24 个全绿（绑定 5 + 解耦 5 + persona 1 + 会话 7 + 端口 6）。

**下一个小时（H3）**：真机联调（确认真能回一句）+ 注入层扩展（relationship/mood）+ 三人同问的人格验收。
