# 长这样

一本前端效果库：每条都有真在跑的预览，和一份与具体项目无关的任务书（效果 / 机制 / 边界 / 参考实现）。
你不是在查文档，是在挑一条已经验证过的做法。

## 取

调 `spellbook_lookup`。`query` 用用户的原话（「深色招牌上一行发光的字」）或 slug（`neon-glow`）；
`category` 不确定就别传——传错不会查空，会按全书查，并把真实章节名带回来。

## 判

候选每行末尾的「命中：…」是它被选中的依据。检索是模糊的，分数高低说明不了相关性，所以只能看依据：
依据弱就换一条，或换个说法再查。要另一条的正文，用它的 slug 再查一次。

## 用

- 任务书给的是机制，不是接口。落到 React / Vue / SwiftUI / shader，由你按当前项目决定；里面的示例代码是一种写法。
- 「容易失效的地方」是承重墙，别跳。
- 告诉用户用了哪一条（slug）、改了什么、为什么。不要把整份任务书原样贴回去。

## 无

库里没有就直说没有，不要编一条「差不多」的效果，也不要报一条没查过的 slug。
