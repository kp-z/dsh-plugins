# 原版后端设计考据：从前端与 API 反推

## 1. 能确定到哪一层

这是一份**外部契约与逻辑职责**说明，不是服务端源码复原。证据以[原版构建件的可读副本](../../../slowvale-mirror/README.md#L10-L18)为主，[历史 API 清单](../../../slowvale-mirror/docs/API.md#L1-L13)作索引。仅审查本地材料，未探测原站。下文把直接可读的行为称为“确认”，把能满足该行为的一种归纳称为“推断”。[镜像 mock](../../../slowvale-mirror/docs/MOCK-BACKEND.md#L2-L5)和当前 XCity 桥只是两种兼容实现，不能用于证明原站内部怎么写。

**核心结论：原版不是“前端跑城市、后端存档”，也不是“每个角色只是一条聊天会话”。** 客户端接收带观察者视角的世界状态、实时变化与生活记录；Phaser 消费视觉片段、加载地图并渲染。权威数据由服务端给出，但无法据此判断它背后有几个服务或用了什么存储。

## 2. 可确认的后端职责

| 职责 | 原版前端看到的契约 | 设计含义 |
|---|---|---|
| 账号、世界、角色 | 登录、世界与角色列表、选角；进入时按所选角色验证快照，档案读取区分目标角色和观察角色。[启动调用](../../../slowvale-mirror/src/js/app.js#L35650-L35682) · [档案与关系请求](../../../slowvale-mirror/src/js/app.js#L35734-L35742) | 账号、居民、观察视角不是同一个 ID；写入权限不能从 UI 按钮推定。 |
| 当前生活状态 | 世界快照包含时钟、天气、市场、地点拓扑、角色公开状态与在场状态、actor 和视觉时间轴；viewer 另带 core、phone、housing 等。[快照校验](../../../slowvale-mirror/src/js/GameView.js#L6439-L6451) | “我看见谁”“他正在做什么”“我可以操作什么”是不同数据，不应塞进同一个状态字段。 |
| 场所与画面 | 场所拓扑、角色位置、场景 actor、场所家具和安装物分别投影；地图资源按场景键定位。[场景响应校验](../../../slowvale-mirror/src/js/GameView.js#L2981-L2996) · [地图资源约定](../../../slowvale-mirror/docs/DATA.md#L6-L18) · [场景工厂](../../../slowvale-mirror/src/js/GameView.js#L99323) | 场所用于业务定位，资源键用于加载地图，工位用于场所内定位。三个值即使都是字符串，也不能互换。 |
| 玩家介入与通讯 | 普通短信、急件、通话、留言、手势是独立请求；短信列表、线程内容和联系人各自读取，线程用消息 ID 分页。[通讯读取](../../../slowvale-mirror/src/js/app.js#L35684-L35692) · [玩家写入](../../../slowvale-mirror/src/js/app.js#L35771-L35783) | 发送请求、当前通话与历史线程并非同一对象。存在短信接口并不证明回复同步生成，更不说明原版使用 DSH 会话。 |
| 历史、记忆与回顾 | 最近日志、断线补齐、角色变化、记忆和回顾是不同读取接口；记忆按日和 ID 分页。[历史 API 调用](../../../slowvale-mirror/src/js/app.js#L35727-L35741) | 当下状态不能替代“他今天发生了什么”；记忆与回顾是独立读法，不等于逐条重放原始日志。是否独立持久化未知。 |
| 生活应用与运营 | 钱包/交易、包裹、交易行情、住宅家具、商店和订单等分别可读；部分查询带已知版本或摘要并接收 304。[交易和手机应用调用](../../../slowvale-mirror/src/js/app.js#L35693-L35723) · [版本化读取](../../../slowvale-mirror/src/js/app.js#L35743-L35755) · [运营端点](../../../slowvale-mirror/docs/API.md#L119-L177) | 能确认原版对外涉及这些业务，不能由此认定数据库表、事务策略或独立微服务。 |

## 3. 实时：快照、变化、场景与历史分别恢复

1. **进入。** 选角色后启动 SSE，发送 `POST /api/game/stream-ticket`（查询参数 `world_id`、`role_id`，空请求体），再用票据打开 EventSource。HTTP 打开连接不等于进入成功；`connected` 或 `resync` 快照建立状态与 cursor 基线。HTTP 世界快照也是恢复手段，不是正常进入时必先拉的唯一路径。[签票和监听](../../../slowvale-mirror/src/js/GameView.js#L3198-L3256) · [进入流程](../../../slowvale-mirror/src/js/GameView.js#L6656) · [恢复分支](../../../slowvale-mirror/src/js/GameView.js#L3565)
2. **推送。** `update` 信封有协议版本、`prev`、`cursor`、`tick_marker`、`kind`、`route` 和压缩负载。前端要求 `prev` 等于该订阅者上次 cursor，同 epoch 且 seq 严格递增，**不要求恰好 +1**。推送区分状态、视觉、家具、场景信号、时钟和日志。状态负责可查询的结果，视觉片段负责怎么走、怎么播，不应让动画成为唯一事实来源。[信封](../../../slowvale-mirror/src/js/GameView.js#L2827-L2909) · [链路校验](../../../slowvale-mirror/src/js/GameView.js#L3037-L3129)
3. **切图。** `scene_state` 只宣告世界和目的场景，前端用该信号的 epoch/seq 请求场景快照，暂存后续更新。响应必须匹配场景并覆盖信号游标；之后过滤已覆盖的更新再继续播。它是切换时的状态基线，不宜把 `after_seq` 理解成该接口只返回事件增量。[场景同步队列](../../../slowvale-mirror/src/js/GameView.js#L5184) · [场景查询](../../../slowvale-mirror/src/js/app.js#L35677-L35682)
4. **补洞。** 常规断线重签票并等待新基线；客户端订阅 URL 没有显式附带旧 cursor。日志另有 `feed_head_record_entry_id` 对账和角色私有路由；部分日志负载损坏可只走补齐，不一定重建整个世界。[断线处理](../../../slowvale-mirror/src/js/GameView.js#L3244-L3264) · [日志补齐](../../../slowvale-mirror/src/js/GameView.js#L4452) · [私有日志异常分支](../../../slowvale-mirror/src/js/GameView.js#L3055-L3076)

历史清单适合作为索引，冲突时以调用代码为准。例如：原前端刷新登录态发 [POST /auth/refresh](../../../slowvale-mirror/src/js/app.js#L35389)；[mock 说明](../../../slowvale-mirror/docs/MOCK-BACKEND.md#L25-L36)里的 GET 写法不代表原契约。

## 4. 角色生活是怎么被看见的

- **角色自己做决定，玩家介入不是远程操控。** 角色面板读饱食、体力和心情；[游戏内说明](../../../slowvale-mirror/src/js/app.js#L14126)把工作、吃饭、交往和睡眠写成角色自主行为。玩家发短信成功后，客户端还[重读互动会话](../../../slowvale-mirror/src/js/GameView.js#L130823-L130833)。因此验短信应拆开“发出”“收到回答”“角色行动”三件事，不能看 POST 返回就判定后两件成功。
- **历史是三种视角。** 回顾根据服务端响应的 `anchor_kind` 区分离开以来等时间窗口，消费时间线、玩家回复与金钱变化；前端还按事件种类拼概览句。记忆按游戏日翻页，“变化”则默认为近七天。七天查询窗口不证明有定时周报，概览文案也不证明调用了模型。[回顾视图](../../../slowvale-mirror/src/js/GameView.js#L18477-L18583) · [记忆与变化 API](../../../slowvale-mirror/src/js/app.js#L35727-L35734)
- **钱有不同语义。** 居民交易账本、玩家钱包支付和商店订单各有入口；不能把它们都当成居民的同一个余额。账本按时间与记录 ID 翻页，未见实际结算规则。[账本调用](../../../slowvale-mirror/src/js/app.js#L35700-L35702) · [玩家钱包](../../../slowvale-mirror/src/js/app.js#L35806) · [商店订单](../../../slowvale-mirror/src/js/app.js#L35836)

## 5. 模拟与模型：产品声明、推断、未知

**产品声明（非服务端实证）：** [原授权文案](../../../slowvale-mirror/src/js/app.js#L13676-L13682)称 AI 用于生成行动、对话和记忆，并列出 DeepSeek 为服务商；游戏说明还描述了离开后有限时长的持续生活。这些是产品承诺，不是后端调度、模型部署或离线结算已经被逆出的证据。

**合理推断：** 至少在逻辑上，需要有推进游戏时间和角色生活的权威计算、处理玩家请求的入口、以及面向当前观察者的状态/历史输出。一个解释得通的过程是：角色根据当下状态选择行动 → 行动推进并改变角色或世界 → 向浏览器发布变化和可回顾记录。这里的箭头是职责关系，**不是已确认的线程或服务拓扑**。时钟、活动进度与画面推进有可观测契约，不足以反推原站内核使用固定 tick。

**仍未知：** 真实数据库和表结构、快照/日志如何持久化，模拟并行或分片、角色决策调度和 LLM 调用频率、提示词/记忆压缩、掉线期间的离线结算、付款的事务与幂等实现。进度字段、历史分页以及 `decision` / `phase` 的日志分支说明客户端能观察到这些视图，不能证明使用事件溯源，也不能证明每个游戏分钟、每个活动都调用模型。[活动进度读取](../../../slowvale-mirror/src/js/GameView.js#L1448-L1464) · [日志条目校验](../../../slowvale-mirror/src/js/GameView.js#L2949-L2976)

## 6. 放回 XCity：保留什么、不抄什么

- **保留目前的职责分界。** XCity 本地模拟推需求、选活动、写状态；桥把现有世界投影成原前端能读的世界快照、场景快照和事件。原版契约能复用，原版业务实现不必复刻。测试中“办公桌切成地图”的故障就是把内核工位身份泄露进了资源键；应该在 [投影层](../src/adapters/slowvale/project.ts#L319-L337)解决，而不是让 Phaser 或侧栏猜。
- **短信能用，不等于整个手机系统已有。** 目前 XCity 有[线程投影](../src/adapters/slowvale/routes.ts#L291-L335)、[会话回复适配](../src/adapters/slowvale/respond-sms.ts#L41)和[当天摘要](../src/sim/day-summary.ts#L59)；它们不等于原版长期记忆、社交或经济系统。兼容接口的常量钱包、空档案、合法空结构也不是功能覆盖。[空态和占位](../src/adapters/slowvale/routes.ts#L406-L465)
- **对“角色像人”最有价值的是一条能回看、能验真的生活链：** 同一角色自主产生行为，进场景能看到，事后能在记录里找到，交谈能引用真实经历。建议先用这条链验现有行为；不因为旧站有商城、支付、招聘和管理台就补建它们。后续若要做任何新机制，再单独定范围。
