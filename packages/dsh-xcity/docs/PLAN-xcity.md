# XCity 推进计划（每小时一轮）

目标：不改 Slow Vale 游戏前端，用 XCity 服务端兑现现有界面功能；三名角色各绑定一条独立 DSH 会话，能在没有玩家指令时主动找活、执行并留下真实产出。

## 模型与运行边界

- 默认模型：**mmt-vision 的 DeepSeek 4.1**。角色会话建联时先核对测试 DSH 的实际模型 ID 与调用权限，再按宿主支持的方式配置和验证。分别核对新建和已有的三条测试会话，不覆盖正式绑定。当前开发会话的子代理路由查询被拒绝，不能据此断言测试 DSH 也不可用；模型未验证前不标绿，也不静默换模型。
- 每小时触发的是**开发验收轮次**，角色心跳由 XCity 服务端驱动，不由这个外部定时任务代跑。
- 只用独立 DSH 测试 profile、端口与绑定；不改游戏构建产物，不重启正式 App，不覆盖他人改动。

## 实施顺序与通过条件

### 0. 日志面板、历史和同页重连（隔离环境已验收）

复现前端拒绝的数据，按现有协议修服务端。用真实活动验证：首次打开有记录、可加载更早、补拉游标和快照水位一致。没有实际验证的 UI 路径不标通过。

### 1. 三条会话逐一打通

先复核实际进程、构建和绑定。沿用现有三名角色（林、梅、周对应的 role.lin / role.mei / role.zhou），先用一名定位断点，再以同样的流程逐一验收，不做三套实现。证据必须同时包含：不同的 DSH 会话 ID、实际模型记录，以及从游戏发出的消息和自动回显的角色回复。短信只提取正文里明确给玩家的短句，不读取思考块。切换 DSH 面板后还要验证同一游戏文档与世界没有重建；只返回 HTTP 200 不算通过。

### 2. 稳定现有世界与协议

按实测问题修通场所、动作、活动进度和日志，不新增对应的平行模型。以一条完整的活动为验收：到正确场所、走到工位、实际开始工作、进度随活动前进、结束后日志可读。保留 decision、phase、notice；验证增量刷新及断线补拉不换 ID、不改历史、不漏记录。

### 3. 复用现有任务系统，接通自主工作闭环

先选一张真实、可验收的小任务。无人发送指令时，让空闲角色的心跳从现有任务中发现并认领，绑定会话执行，真实结果回写现有任务。用三名角色验证不会重复领单、忙碌时不会重复投递、不抢占用户任务。没有可做任务就待命；失败保留原因，不靠计时或动画报完成。不引入新模式开关，也不先做“角色自行创造任务”。

### 4. 逐项兑现其余前端能力

以 [前端能力清单](FRONTEND-SURFACE.md) 和 [API 覆盖](API-COVERAGE.md) 为范围，包括场景交互、角色间交流、资产与背包、职业与业务、订单、生活和社交。按实际可点击入口建立验收证据；前端枚举不是业务规则。没有可核实的规则或数据就标明缺口，核心概念需确认，不能用固定值或空响应报完成。上一阶段没通过不宣称完成；碰到外部阻塞可继续做不依赖它的项目。

## 每轮收尾

每轮只交付一个可验证的切片；实际入口用浏览器核验，构建和测试检查真实退出码，校验镜像未改。把通过证据、未验证项、阻塞与下一步写入 [轮次台账](PROGRESS.md)。历史结论只作线索，不作本轮验收证据。
