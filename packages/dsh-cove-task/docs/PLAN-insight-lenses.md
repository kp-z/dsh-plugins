# 诊断洞察 v2：长期行为洞察 + 多视角

> 状态：设计定版 v1（2026-11-28 00:20）
> 目标：把「诊断」从「今天哪条有问题」升级成「**基于你的长期行为给出可检验的建议**」，并成为洞察的默认 tab。
> 约束：不新增 tab、不做人格测评、不让模型算数字、每条建议必须能被下一轮数据推翻。

---

## 0. 一页结论

- **入口**：洞察默认落在「诊断」tab；不新增第四个 tab。
- **数据**：全部本地算（时间戳 / 延期 / 归因 / 每日快照），模型只做解释与取舍。
- **产物**：每期**一个**主洞察，结构固定：事实 → 假设 → 反证条件 → 二阶后果 → if-then 动作 → 验收指标 → 到期回顾。
- **视角**：矛盾论（收敛器）、逆向、二阶、价值澄清、结构；CBT 只当话术护栏（默认关）；**MBTI 不做**。
- **窗口**：≥14 天才给长期结论；14–28 天只给节奏类；28 天以上才给归因与二阶。
- **回顾**：结论带 `until`，到期在卡片上提示「还成立吗」，点一下重跑。

## 2. 数据边界（决定了方案的上限）

- 飞书历史已完成任务**默认不拉**（会 190+ 条撑爆看板），本地只保留「面板里标完成 / 开过会」的完成项 → **长期窗口 = 开始用 Cove 至今**。
- `metricsByDay` 是唯一的跨天快照（WIP/完成/完成度/周期分位），从装上开始累积。
- 所以：
  - 样本 < 14 天：不输出长期结论，只输出「先积累样本（还差 N 天）」。
  - 14–28 天：只输出**节奏类**（周内分布、进出台账），不做归因。
  - ≥28 天：允许归因、二阶与价值冲突。
- **可选后手**（默认不做）：一次性只读拉飞书已完成任务，算完指标即丢。需单独确认，且不进看板。
- 注意：`feishu-sync` 后端的 `listTasks` 目前不接 `includeCompleted`（`index.js:2521`），设置里那个开关对它无效 → **UI 不许承诺「全历史」**，只说「从开始使用 Cove 起」。

## 3. 洞察链路（七段）

1. **采样**：窗口 12 周；输出 `windowDays / sampleDays / coverage`（有多少天有快照）。
2. **事实**：`behavior.js` 本地信号（全部带数字、窗口、样本量）。
3. **异常**：与**自己的历史分位**比（p50/p85），不用绝对标准。
4. **解释**：选 1–2 个视角 → **一条**假设 + 反证条件。
5. **二阶**：一条「然后呢」+ 一条预防条款。
6. **动作**：if-then + 验收指标 + 时间窗。
7. **回顾**：到期回看指标；不成立换假设，不加重执行压力。

> 与 flomo 的差别：flomo 读你的**叙述**，我们读你的**痕迹**。所以每个视角都必须落到数字，否则就是占星。

## 4. 视角库（5 用 1 弃）

| id | 视角 | 问什么 | 触发条件（本地） | 产出 | 护栏 |
| --- | --- | --- | --- | --- | --- |
| contradiction | 矛盾论 | 这几条里哪条是主要矛盾？ | 异常 ≥2 条 | 只留 1 个抓手 + 为什么它规定其余 | 不允许并列；次要矛盾只准列 1 条「暂不处理」 |
| inversion | 逆向 | 想保证继续延期，该怎么做？ | 同一延期桶 ≥3 次 或 重承诺 ≥3 次 | 3 条「停止做的事」 | 不许写「不要拖延」这种非动作 |
| second_order | 二阶 | 照这个改法，两周后会怎样？ | 每条建议都跑 | 1 条后果 + 1 条预防条款 | 只推 1 步，不写「可能引发连锁反应」这种空话 |
| values | 价值澄清 | 你说重要的，和你时间实际在哪？ | P0 的任务活动占比 <15% 且 WIP>3 | 冲突点 + 取舍建议 | 只看行为，不做价值观问卷 |
| structure | 结构 | 是流程问题还是「不够自律」？ | 同类卡点 ≥3 次 | 改模板/缓冲/前置条件 | 禁止人格归因 |
| cbt | CBT（解释风格） | 这是事实还是解释？ | 任务标题/说明里绝对化措辞 ≥2 次（默认关） | 重述 + 更准确的解释 | 不临床、不诊断、不贴标签 |
| mbti | MBTI | — | — | — | **不用**（信度争议 + 对任务行为无预测力 + 易变标签） |

**选择规则**：按 `contradiction > inversion > values > structure > second_order` 优先级触发；`second_order` 在任何建议后强制跑；每期最多 2 个视角，默认 1 个。

## 5. 理论库：两层，别堆

来自成甲《好好思考》的分层（经验技巧 / 方法流程 / 学科原理 / 哲学视角），我们只用两层：

**L1 视角（哲学/学科：怎么看）**
矛盾论（主要矛盾）、逆向（芒格）、二阶（Howard Marks）、价值理论（Rokeach/Schwartz）、系统/结构。

**L2 模型（方法/技巧：怎么做，必须挂数字）**

| 模型 | 一句话 | 挂在哪个信号 |
| --- | --- | --- |
| 实施意图 if-then | 把「该做」变成「当 X 时我就做 Y」（Gollwitzer & Sheeran 2006，d≈.65） | 启动延迟、deadline 挤压 |
| 参考类预测 | 用同类任务的历史 p85 估，不用直觉（Kahneman & Tversky；Flyvbjerg） | 承诺偏差 |
| 学生综合征 / 帕金森定律 | 工作膨胀到填满时间，人倾向deadline前才开工（Goldratt 1997；Parkinson 1955） | deadline 挤压 |
| 利特尔法则 + WIP 上限 | L=λW：并行越多，单条越慢（Little 1961） | WIP、净积压 |
| 注意力残留 | 切换后前一件事仍占注意力（Leroy 2009） | 跨项目切换 |
| 蔡格尼克效应 | 未完成事项持续占用注意力，需要明确关闭（Zeigarnik 1927） | 长期挂账 |
| 习惯形成尺度 | 自动化中位 66 天（18–254），漏一天影响小（Lally 2010） | 新习惯建议的时间窗 |

规则：**先 L1 选角度，再 L2 给做法**；L2 每条必须对应一个数字，禁止只有理论名。

## 6. 输出契约（只 1 条，防信息过载）

```json
"longTerm": {
  "lens": "contradiction|inversion|values|structure|second_order",
  "fact": "一条数字，必须能在行为档案里原样找到",
  "hypothesis": "≤30 字",
  "falsifier": "什么情况这条不成立（≤30 字）",
  "secondOrder": "≤30 字",
  "action": "if X then Y（≤40 字）",
  "metric": "验收指标",
  "until": "YYYY-MM-DD"
}
```

**存储**：新键 `state.longTerm`（进 `DEFAULT_STATE` + `persistState`），字段 `{ at, until, promptRev, windowDays, sampleDays, data }`。
**不复用** `insightResults`：那份只返回「今天 0 点之后」（`index.js:8687`），跨零点就空，和「7 天后回顾」直接冲突。

**校验（宿主侧，照 `normalizeDelayPatterns` 的做法）**
1. `fact` 在档案文本里找不到 → 丢弃；
2. `lens` 不在白名单 → 丢弃；
3. 缺 `falsifier` → 丢弃；
4. 样本天数不足 → 整块丢弃，只留「样本 N 天」提示；
5. 单条上限：一行 40 字以内，超出截断不重试。

## 7. UI

- 默认 tab：`DEFAULT_BUTTONS` 顺序 = 诊断 → 早会同步 → 写入评论；`selected` 兜底优先 `diagnose`。老配置不擅自改排序。
- 总览卡片：在「下一步」下方加一块「长期」（`longTerm`），渲染 3 行：事实（灰）→ 假设（黑）→ 动作（品牌色）；hover 显示视角 + 反证条件。
- 回顾：`until` 过期 → 卡片顶部一行「这是 11-21 的判断，还成立吗」，点一下重跑。
- 侧栏窄卡：只放 summary，不塞 longTerm。
- 无 longTerm（样本不足/旧宿主）→ 整块不渲染，不留空壳。

## 9.5 设计论证（先自我红队，再落代码）

| # | 质疑 | 回答 |
| --- | --- | --- |
| Q1 | 为什么不单开一个「长期洞察」tab？ | 增量信息只有一块（长期模式），其余（结论/问题/下一步/改进）与诊断同构；单开 tab 会把「今天的事」和「长期的事」劈成两处，还要再养一套生成/缓存/持久化。入口成本 > 收益。 |
| Q2 | 为什么每期只给 1 条主洞察？ | 建议的转化率和条数成反比；flomo 也是「选一个视角」；矛盾论要求先分清主次。次要问题只保留「暂不处理」一行。 |
| Q3 | 为什么 MBTI 不做？ | 重测信度有争议（Pittenger 1993：5 周 50% 变类；官方反驳称引用旧版数据），更关键是它对**任务行为没有预测力**，且一旦写进卡片就变成标签。可留「用户自述偏好」字段，但模型不得据此下结论。 |
| Q4 | 为什么不用 CBT 读会话？ | 隐私与成本双高，且文本里的一句话不足以做归因；先用任务语言里的绝对化措辞做轻量触发，默认关。CBT 的主要价值是**护栏**（不把结构问题说成人格问题），不是诊断。 |
| Q5 | 为什么数字一定要本地算？ | 模型算数会漂，且漂了无法复现；本地算才能被测试、被回填、被用户核对。模型只做「解释与取舍」。 |
| Q6 | 为什么和自己历史比，而不是行业基准？ | 个体节奏差异远大于基准差异；样本小时基准毫无意义。自己 vs 自己才能排除「你本来就慢」这种噪声。 |
| Q7 | 这套设计怎么被证伪？ | 两个硬指标：R8 的 12 场景通过率 <8/12；或真实使用 3 周后，用户仍只在看结论、没有执行过一次 if-then。任一成立就回滚到「单条建议 + 28 天履约」，并删掉 longTerm 的二阶字段。 |
| Q8 | 和 flomo 到底什么关系？ | 借它的**形态**：把道理变成工具、一次一个视角、不生成替代你思考的内容；不借它的**输入假设**（它读叙述，我们读痕迹），所以每个视角必须落在数字上。 |

**签名**
```js
export function buildBehaviorProfile({ tasks, metricsByDay, delayAttributions, now, ignoreWords }) {

```

**信号（id | 公式 | n | 输出文本行）**

| id | 公式 | n | 文本示例 |
| --- | --- | --- | --- |
| weekday | 近 8 周 `completedAt` 按 `getDay()` 计数 | 完成条数 | `周节奏（n=83）：四 34 / 五 18 / 三 16 / 二 15 / 日 13 / 一 5 / 六 4` |
| flow | 按周（周一起）统计 `firstSeenAt` 新增 vs `completedAt` 完成，取 8 周 | 周数 | `进出台账（8 周）：新增 9/12/…；完成 6/8/…；净积压 +3/+4/…` |
| wip | 每日 `metricsByDay[day].wip`，取 p50/p85 | 有快照天数 | `在跑（n=34 天）：中位 4，85 分位 7` |
| lead | 已完成且 `firstSeenAt>0` 的 `completedAt-firstSeenAt`，p50/p85 | 条数 | `进列表→收口（n=105）：中位 2.1 天，85 分位 6.8 天` |
| promise | `expectedAt>0 && completedAt>0`：提前 / 准时 / 延期；另算「完成但没 ETA」比例 | 条数 | `承诺兑现（n=36）：提前 21 / 延期 15；完成但没设预期 69/105` |
| deadline | `(expectedAt-completedAt)/DAY_MS` 的分布，统计「截止前 <1 天完成」占比 | 条数 | `deadline 挤压（n=36）：72% 在截止前 24h 内完成` |
| switching | 每周有活动的项目集合大小，取 p50；活动 = 任一任务 `taskActivityAt` 落在该周 | 周数 | `切换（8 周）：每周平均碰 4 个项目，最多 7 个` |

**硬性约束**
- 所有时间用传入的 `now`，**不调 `Date.now()`**；按本地时区取日/周（复用 `dayStart` 的口径，函数内自己实现）。
- `n<5` 的信号进 `gaps`，不写进 `text`（模型看不到就不会编）。
- 数值统一保留 1 位小数；比率给整数百分比。
- `text` 的每一行都必须能被 `fact` 原样引用（校验靠字符串命中）。
- 不读 `state`、不读 process.env、不写文件。

**测试用例（`test/behavior.mjs`）**
1. 空数据：`text === ''`，`gaps` 含全部信号；
2. 单任务：各信号 n=1，全部进 gaps；
3. 本机数据回放：用 §12.5 的数字做断言（105 / 34 天 / 周四 34）；
4. 时区：23:59 完成算当天，00:01 算次日；
5. 脏数据：`startedAt: null`、`completedAt: 'x'`、重复 id 不抛错；
6. 稳定：同一输入两次调用输出完全一致（无 `Date.now`、无随机）。

## 10. 风险

1. **数据太薄**（最大风险）：多数人装上不到两周 → 长期结论长期空窗。缓解：14 天门槛分档；空窗期只给「周节奏 + 先积累」。
2. **模型编数字/堆理论**：靠 `fact` 命中 + 视角白名单 + falsifier 三重复核，宁缺勿凑。
3. **重复表达**：28 天履约与 12 周模式会重叠 → 约定：**28 天讲兑现，12 周讲模式**，同一结论只出现一次。
4. **成本**：诊断走会话，材料约 +800 tokens；生成是手动触发，可接受。
5. **伪精确**：所有指标给分位不给单点预测；不做「照做提升 X%」。
